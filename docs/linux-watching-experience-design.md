# Linux 连续追剧体验设计

日期 2026-11-07 · 含实施验证

打开选集时直接找到当前进度，提前知道下一集能否起播，放大画面后仍能随手查看分集与播放信息。播完一季时，可以从同剧下一季已有的进度继续看。开启时间轴弹幕时，按本集视频的播放位置显示。

选集与全屏共用播放状态。取源、备用入口、会话恢复和重试限制沿用现有方案，本设计将实际执行阶段呈现在选集里。 [App 取源恢复方案](linux-app-source-recovery-plan.md) · [播放与转码优化计划](linux-playback-optimization-plan.md)

## 1. 选集右上角显示下一可播集

在「选集」标题右侧显示一行摘要，例如「下一集 · 第 178 集 · 已就绪」。目标采用现有连播规则，跳过锁定集。当前目录没有后续可播集时，显示「暂无下一可播集」。分集按钮仅在有相关任务或结果时显示状态，长列表保持简洁。

| 状态 | 显示条件 |
| --- | --- |
| 待准备 | 已加入后台队列，任务尚未开始。 |
| 正在取源 | 正在获取本集的播放信息。 |
| 正在重连 | 正在尝试备用入口或恢复会话。已知可重试时间时，展开状态可查看。 |
| 正在缓冲 | 正在获取视频数据。已知总量时可显示百分比。 |
| 正在转码 | 当前解码设置需要兼容文件，转换任务正在运行。 |
| 已就绪 | 当前清晰度和解码设置下，有已校验且可以复用的本地视频或播放缓存。 |
| 准备失败 | 本轮已结束，展开状态可查看原因并按现有重试条件重试本集。 |

「已下载」继续表达手动下载的文件状态。预缓存就绪、已下载和已看过分别显示，当前集的选中样式优先。预缓存关闭且当前没有可用缓存时，摘要可显示「播放时准备」。

点选正在准备的分集时，播放器接管同一任务。后台状态来自实际任务，按剧、集、画质和请求身份关联。切剧、换画质、变更解码方式或清理缓存后重新判定，旧任务的状态只归属于原请求。 [预取与选集入口](../src/components/Player.jsx) · [任务与播放缓存](../main.js)

## 2. 应用内全屏

- 在控制条提供独立的「应用内全屏」入口。播放器填满应用窗口的可用区域，收起主导航和页面操作栏，画面按当前比例设置显示。横屏、竖屏及最大化窗口共用这一模式。
- 控制条显示时，右上角提供「选集」和「信息」。有足够的画面留白时将抽屉放在留白处，空间紧张时用可关闭的浮层叠在画面上。打开选集时复用同一份分集列表和下一集摘要。
- 鼠标闲置时可隐藏按钮和控制条。抽屉打开、键盘焦点在控件内或用户正在拖动进度条时保持可操作。`Esc` 先关闭抽屉，再退出应用内全屏。关闭抽屉后焦点回到打开它的按钮。
- 切换布局时复用当前视频元素，连续保持播放位置、暂停状态、倍速和音量。全屏中切集、换季或重试时继续使用同一播放界面。

## 3. 长剧定位

- 每次打开选集时将当前集滚入可见区域。用户开始浏览后由用户控制滚动。切集后更新高亮，选中的分集在视野外时才滚动定位。
- 提供「跳到第 N 集」，输入有效集数后定位到对应按钮，由用户确认播放。锁定集可定位并显示锁定状态；当前目录缺少该集时在输入框旁提示。
- 普通播放页与全屏选集共用当前集和定位规则，支持键盘输入、确认与返回播放器。

## 4. 已看过的分集标记

- 给实际播放过并保存过有效进度的分集加淡色标记，辅助文字为「已看过」。详情打开、预缓存、仅拖动进度条都属于准备或定位操作，标记由真实播放进度产生。
- 标记按剧季和分集保存，允许先看第 178 集再回看第 176 集。切回列表时保留这两个标记，第 177 集按其自身记录显示。
- 旧版按剧季保存最近一次续播位置。升级时用这条已有记录标记对应分集，其他分集在实际播放后逐步补齐。已看标记与每季的续播位置分别读取。 [现有观看记录](../src/native/watch-history.js)

## 5. 全屏信息抽屉

抽屉显示当前剧名、季和集，以及实际使用的媒体信息。片源可显示为 App、网页、其他来源或本地文件；清晰度显示实际视频尺寸，例如 `1080 × 1920`；播放方式显示「原片直放」或「H.264 兼容播放」。当前在等待时显示真实准备阶段。

片源切换时重新读取当前媒体，尚未得到的信息显示「待确认」。选择的画质档位和实际分辨率可同时展示。原片直放与硬件解码是不同信息，只有确认了实际解码方式才显示硬解或软解。

## 6. 跨季续播

- 当前季最后一集实际播完后，若现有季关系中有唯一的下一季，显示「继续第 2 季」。已有进度时在按钮旁显示「接着第 8 集看」等提示；首次观看时从该季第一可播集开始。
- 点击后先保存当前季进度，再按下一季自己的记录打开。当前季还有锁定尾集时，保持「已播完可播放集数」的准确提示。
- 同一季号有多个候选或季关系待确认时，打开现有季选择入口，由用户确认剧名。用户也可以从选集抽屉主动切季。 [现有季关系规则](../src/native/season-groups.js)

## 7. 预缓存档位

播放器提供「关闭」「仅下一集」「后两集」三个档位，旁边显示当前播放缓存占用。设置即时保存，默认「后两集」，对应当前 Linux 播放器的预取数量。

| 档位 | 播放中的后台行为 |
| --- | --- |
| 关闭 | 点播或切集时按需准备，已有有效缓存仍可直接播放。 |
| 仅下一集 | 只准备紧邻的下一可播集。 |
| 后两集 | 先准备下一可播集，再准备后面一集。 |

档位控制主动准备多少集，缓存文件继续按现有保留窗口和空间规则管理。缩小档位时撤销范围外的后台任务，已由前台接管的播放任务继续执行。已有合适本地文件的分集直接参与就绪判定。缓存占用统计与手动下载文件分开。

## 8. 时间轴弹幕与加载失败

接入时间轴弹幕前，「弹」按钮读取官网公开的本集评论，并按顺序滚动显示。2026-11-07 在最近播放的一集复现加载失败，官网返回 HTTP 302，跳转后的播放器数据对应另一集。现有分集校验可以阻止串集。用上游 `v6.2` 的弹幕请求读取同一集，首批返回 2 条带播放时间点的弹幕。 [公开评论来源](EPISODE_COMMENTS.md) · [上游时间轴弹幕说明](https://github.com/jackotom/hongguo-drama/blob/v6.2/docs/release-2.9.md)

- 在「弹幕设置」提供「时间轴弹幕」和「本集评论」两种来源。时间轴弹幕按视频当前播放时间显示，复用弹幕开关、字号、透明度和屏蔽词设置，并记住所选来源。
- 暂停时暂停弹幕。拖动进度、断点续播、切集和倍速变化时，以当前媒体时间重新定位。普通播放与应用内全屏使用同一叠层和状态，切换布局时维持同步。
- 加载结果区分「本集暂无弹幕」「弹幕接口暂不可用」「已加载部分弹幕」与「官网未公开本集评论」。部分加载失败时保留已获取的弹幕，提供重试。只有校验为当前集的公开评论才可作为备选，按评论方式显示。
- 按来源、剧和分集关联请求及缓存。切集后迟到的数据归原分集。弹幕取源失败时视频继续播放。同步上游实现时保留 GPL-3.0 许可及署名，先用实际分集验证返回的时间点与当前片源相符。

## 实施顺序

1. 先为预缓存接出真实状态，完成下一集摘要、档位和长剧定位。沿用现有播放请求与缓存队列。
2. 完成分集观看标记与跨季续播，覆盖旧数据读取和多季各自保存进度。
3. 将同一套选集和状态接入应用内全屏，补齐信息抽屉和键盘交互。
4. 接入时间轴弹幕，完善评论源错误说明，再核对普通播放和应用内全屏的弹幕同步。

## 验收场景

- 在 180 集的剧中从第 176 集跳到第 178 集，重开选集定位到当前集。跳转框能定位任意已列出的集号，已看标记与下载、预缓存状态可以同时辨认。
- 模拟下一集取源、重连、缓冲、转码、就绪和失败。等待期间点该集，当前播放复用同一任务。切剧、改画质、清缓存后，摘要与实际可用媒体一致。
- 播放过程中切换三种预缓存档位，检查后台任务数量、前台接管、已有缓存复用以及重启后设置读取。
- 在 Ubuntu Wayland 的普通、最大化和竖屏窗口中切入应用内全屏，反复开关抽屉、切集和退出，确认画面比例、音频、进度与暂停状态正确。核对信息抽屉随实际片源变化更新。
- 用旧数据和新数据分别验证续播及已看标记。测试唯一下一季、多个候选和锁定尾集，确认每季的进度独立保存。
- 用官网跳转到其他分集的样本核对评论身份校验，并验证同集时间轴弹幕。覆盖空列表、请求失败与部分返回。实际播放中暂停、拖动、倍速、切集和切全屏，检查弹幕显示与视频时间一致。

实现后使用现有播放回归和前端构建，再用独立应用配置进行 Ubuntu 桌面试播。 [开发与验证说明](DEVELOPMENT.md)

## 验证记录

- 播放回归 60 项全部通过，包含真实媒体文件与 HLS 检查。前端生产构建通过。
- 用独立配置在 Ubuntu Wayland 实播 1920 × 1080 的红果 App 片源。普通窗口、最大化窗口和竖屏布局进入应用内全屏后，视频区域填满窗口。检查了选集定位、信息尺寸、`Esc` 先关闭抽屉、退出全屏保留同一视频和暂停状态、档位保存与已看标记。
- 曾遇到公开评论跳转的分集通过时间轴接口取得弹幕，桌面试播验证拖动后出现弹幕、暂停后弹幕停在原位。部分结果保留、错集拒绝和时间轴定位有离线回归。
- 跨季续播、档位关闭时撤销后台任务、过期进度隔离和缓存文件失效由回归覆盖。
