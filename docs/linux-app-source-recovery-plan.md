# 红果 App 取源恢复方案

目标是缩短 Linux 桌面端短剧连播时的取源中断。先在当前集播放期间准备下一可播集。遇到空响应时，优先用现有会话试备用入口，必要时才更新匿名会话。

## 实测依据

| 对照 | 观测结果 |
| --- | --- |
| 第 178 集，同一会话、同一入口、全新连接 | 空响应后等了 62 秒，再请求仍收到 `HTTP 200`、0 字节。更新会话后拿到播放地址。 |
| 第 179 集，同一会话切换入口 | 主入口返回空正文，备用入口约 137 毫秒返回播放数据。 |
| 第 179 集，提前更新会话 | 距上次更新约 10.5 秒时，新会话注册成功。更新完成后，模型请求约 166 毫秒返回播放数据。 |

上述时间测的是取源请求，实际起播还包括下载、校验及解码。样本说明备用入口和提前更新都能恢复部分请求，服务端返回空正文的具体规则仍未知。10 秒作为首轮验证参数。现有 Linux App 取源使用匿名设备会话，原上游的官网登录功能与该取源路径独立。

## 恢复流程

1. **先复用可用结果。** 继续按片源、分集和所选画质复用经过校验的本地原件、播放缓存和在途任务。当前集开始播放后，先准备紧邻的下一可播集，跳过锁定集。
2. **主入口空响应后立即试备用。** 沿用同一会话，按备用入口重新签名并使用新连接。备用返回有效模型后按原流程继续校验、下载和缓存。只把播放模型请求的 `HTTP 200` 空正文归入这条快速恢复路径。
3. **主备均空时只更新一次。** 当前集和紧邻的下一可播集可申请快速恢复。同进程两次会话更新的启动时间至少相隔 10 秒，多个请求共享一次更新。已满 10 秒就立即更新。冷却尚未结束时，当前集最多等剩余的短间隔。下一集可以趁当前视频继续播放时等待，切到这集就接管同一任务。
4. **用新会话重取一次。** 优先尝试本次或最近一次成功过的入口，缺少成功记录时使用主入口。单轮最多三次模型请求，含原会话主入口、原会话备用入口和新会话重取。沿用前台 30 秒取源上限，给注册预留预算。预算耗尽时结束本轮并提示可重试。
5. **连续失败后退避。** 若注册失败，或新会话仍返回空正文，从失败时起暂停快速更新 60 秒。此时仍可复用已验证的缓存和有效地址，待播集提示何时可再次尝试。外围重试收到主备均空的结果后结束这一轮，避免马上重走三次模型请求。

| 任务 | 取源优先级与更新资格 |
| --- | --- |
| 当前正在等待播放的集 | 优先取源，可申请一次快速更新 |
| 紧邻的下一可播集 | 当前播放稳定后开始预取，可申请一次快速更新。切集时提升同一任务 |
| 更远的预取 | 下一集准备好后再开始，可尝试备用入口。遇到主备均空时停止推进本轮预取 |
| 手动下载、搜索和其他片源 | 沿用各自已有的取源策略，共享已经成功建立的会话 |

## 实现落点

| 位置 | 改动 |
| --- | --- |
| [App 取源](../src/native/app-source.js) | 调整为主入口、同会话备用入口、必要时更新后重取。区分模型接口和补充媒体信息请求的空响应，并返回入口和实际恢复结果。 |
| [会话管理](../src/native/playback-device.js) | 保留同进程共享注册。集中管理短间隔、失败退避和在途更新。普通调用沿用原有更新资格。取消一个任务时，其他仍在等待的任务继续共享注册。 |
| [播放准备](../main.js) | 从当前播放窗口判定当前集和下一可播集。预取提升为前台时复用下载与重试等待。主备均空由取源流程处理，媒体下载失败仍走现有媒体恢复流程。 |
| [播放器](../src/components/Player.jsx) | 后台恢复时继续播放当前集。前台等待时区分正在重连、正在缓冲和正在转换。跳集、换剧、改画质或退出时取消过期等待，旧请求的结果只可交给仍在等待它的任务。 |

日志只记录取源阶段、主备入口标签、响应大小、耗时、是否实际更新会话和结果。提示语依据实际执行结果区分「会话已更新」「仍在冷却」和「补充播放信息返回空响应」。

## 验收

- **模拟回归。** 复用现有取源恢复、会话和预取检查。覆盖备用入口成功且零额外注册、主备均空后快速更新一次、10 秒冷却内任务合并、更新失败后 60 秒退避、补充请求空响应的独立提示，以及预取提升、切集取消和缓存复用。
- **真实短集连播。** 用独立应用配置，从最近复现的分集开始连续播放至少三集。记录从上一集结束到下一集首帧的等待、备用入口命中、会话更新次数和剩余失败次数。已有预取缓存的切集与现场取源恢复分别计时。上游当时若没有返回空响应，用可控模拟覆盖失败路径，并分开报告。
- **交付验证。** 跑完带真实媒体样本的 `npm run test:playback` 和 `npm run build:react`。通过标准是备用有效时无需等待更新，允许快速更新时无需等待旧的一分钟窗口，重复失败仍按上限退出。方案与播放和转码优化分别评审。
