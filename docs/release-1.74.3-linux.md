# Linux v1.74.3 · 修复 App 高清源取流 403

- 实测发现 App 播放接口可返回多档清晰度，但程序给媒体请求附带网页 Referer，会使部分 App 视频 CDN 返回 HTTP 403，导致高清源实际无法使用。
- 为 App 媒体候选明确设置“不发送 Referer”。下载、在线播放、磁盘缓存和 HLS 准备遵循该策略；403 重试也不再重新补上被拒绝的 Referer。
- 网页及其他来源继续保留其需要的请求头；视频地址、密钥与请求头策略仍随候选来源绑定。
- 保持真实视频尺寸校验。选择 1080P 时未达到要求会提示，不静默降到网页低清源；先前自动模式留下的低清缓存可通过切到 1080P 重新取源，手动下载继续保留。

## 验证

40 个离线回归脚本通过，新增覆盖 App 不发送 Referer、大小写不同的头也能移除、保留 User-Agent/Range、403 重试不补回 Referer，以及其他来源的 Referer 行为不变。

另经生产 `prepare-online-play` 链路实测：《纵棠》第 4 集从 App 源下载、处理加密封装、落盘并成功解码，实际尺寸为 1080×1920、编码 HEVC。三个不同剧集的 App 视频请求均在带网页 Referer 时返回 403；上述样例移除后返回正常视频数据，完成了完整下载及解码验证。

该样例 App 视频码率约 0.355 Mbps；此前实测同集网页视频为 360×640、H.264、约 0.320 Mbps。编码不同，不能只按码率数值比较画质；1080P 也不代表所有剧集都提供高码率版本。以上是当前样例，其他剧集与网络环境需分别验证。

```sh
npm run test:playback
# 可选：联网运行真实样例，临时文件和测试数据会自动清理
node scripts/check-live-app-playback.cjs
npm run package:linux
node scripts/check-linux-update-bundle.cjs
```

1.74.1 及更新版可使用设置中的一键更新；更早的本机安装可运行新版目录中的 `升级现有安装.sh` 原位升级，自动关闭旧版残留进程。
